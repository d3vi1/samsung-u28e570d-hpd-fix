# Windows laboratory implementation

This is laboratory code for the unofficial **1005.0-experimental.1** modification of Samsung 1004.5. **Hardware execution is disabled in this repository.** `ExperimentalPolicy.HardwareEnabled` is `false`, and `FirstEdidSerial` is the non-device placeholder `LOCAL_PROFILE_REQUIRED`.

The implementation is not generally validated for Samsung monitors, MStar scalers, NVIDIA GPUs or arbitrary firmware. Offline tests establish properties of the parser and transaction code; they do not establish successful physical flashing, recovery, booting or standby behavior. No firmware binary, monitor dump, EDID, serial number or private hardware-run artifact is included. See the [upstream project README](../../README.md) for the patch rationale, build procedure and behavioral test matrix.

## Files and local inputs

Run the commands below from the repository's `windows` directory, using PowerShell 7 on Windows. The simulator can also run under Windows PowerShell 5.1.

| Component | Purpose |
|---|---|
| `FirmwarePackage.cs` | Pure package, checksum and DEFLATE validation |
| `FlashTransition.cs` | Pure image planner and transaction engine with a simulated-device interface |
| `ExperimentalPreparation.cs` | Exact artifact and directional-plan pins; disabled local hardware profile |
| `NvidiaExperimentalAdapter.cs` | Laboratory NVAPI adapter, interlock and result handling |
| `../NvidiaMstarRead.cs` | Generic serial-selected NVAPI transport and read helpers |
| `../NvidiaMstarSpi.cs` | SPI primitives only; no historical per-unit upgrade profiles |
| `Invoke-Experimental10050.ps1` | Offline validation by default; disabled hardware entry points |

Supply these files locally; they are ignored by Git and are not part of the source bundle:

```text
inputs/baseline-1004.5-full.bin     exact verified 2 MiB baseline
inputs/official-1004.5.bin          official package used as the reference
inputs/fixtures/1002.0.bin          historical parser-suite fixture
inputs/fixtures/1003.1.bin          historical parser-suite fixture
experimental/artifacts/candidate-1005.0-zlib-1.3.2.bin
                                  candidate generated by the upstream build
```

Historical fixtures are unnecessary for `Validate` but both are required by the complete parser test suite. They may be complete dumps or package files containing the expected package prefix. The candidate must be generated locally, then match the retained pins. Recompression with another zlib version can change its package identity even if the expanded application is identical.

## Offline validation

```powershell
pwsh -NoProfile -File .\experimental\Invoke-Experimental10050.ps1 `
  -Mode Validate `
  -CandidatePath '.\experimental\artifacts\candidate-1005.0-zlib-1.3.2.bin' `
  -OutputDirectory '.\experimental\artifacts\validation-local-01'
```

`Validate` is the default. It loads only the offline C# components and does not construct a NVIDIA object or access a monitor. Default input paths are `inputs/baseline-1004.5-full.bin` and `inputs/official-1004.5.bin`; explicit alternate paths must still match the pinned bytes. Use a new output directory for every invocation.

Generated outputs are `baseline-1004.5-full.bin`, `expected-1005.0-full.bin`, `candidate-package.bin` and `validation-and-plans.json`. They are local artifacts, not distributed evidence files. Validation checks the package identity, header and embedded lengths, both CRC16s, both CRC32s, bounded DEFLATE expansion and its exact boundary, expanded identity, version, and bootstrap/PM51 preservation. The candidate preserves the uncompressed main head except for its recompression-dependent length word.

## Offline tests

The simulator needs no firmware files:

```powershell
pwsh -NoProfile -File .\experimental\Test-FlashTransition.ps1
```

It has 19 cases covering forward/reverse transitions, longer-candidate tail restoration, preflight failures, changed plans, post-erase errors, sector/full verification, status failures, logging errors, rollback failure and reset inhibition. It performs no monitor I/O.

After supplying the local inputs and generating the candidate, these additional suites are available:

```powershell
pwsh -NoProfile -File .\experimental\Test-FirmwarePackage.ps1
pwsh -NoProfile -File .\experimental\Test-ExperimentalPreparation.ps1
```

The parser suite expects three known firmware fixtures and checks 19 rejection cases. The preparation suite checks the exact reproduced candidate, pinned plans, mutable-DTO rejection, disabled hardware entry and disposal-error handling. Compiling the adapter for these tests does not construct a monitor connection.

## Transaction and recovery boundaries

`Forward` and `Rollback` are explicit laboratory modes, but the repository policy rejects them before NVIDIA construction. The retained adapter expects a particular `EF4015` flash/status/SFDP profile; it is not a general programmer.

Before mutation, the engine checks the complete 2 MiB source and unchanged status. It verifies each changed sector and the full target. On an in-process failure it attempts every touched sector using the exact full source and 32-byte programming pages, then verifies the complete source and status. Reset permission starts false and is withheld whenever image integrity cannot be established. Logging failures cannot interrupt restoration.

The reverse plan restores the complete baseline, including bytes occupied only by the longer candidate. Overlaying the shorter official package on the candidate is not equivalent. Main-array dumps do not cover separate EEPROM, internal NVM or security/OTP storage, and firmware can update configuration after boot.

The adapter uses a named mutex and a durable local recovery marker at:

```text
%LOCALAPPDATA%\SamsungMstarExperimental\<configured-edid-serial>-recovery.txt
```

An unresolved marker blocks another hardware entry. Deleting it is not a recovery operation. The ordinary reverse transition requires an exact known source and a responsive device; it is not a recovery path for an arbitrary partial image. Power loss, process termination, lost ISP access and a correctly flashed image that fails to boot have no guaranteed automatic recovery in this code.

Post-exit EDID/DDC checks cover basic connectivity only. Physical standby/wake behavior and the upstream regression matrix require separate hardware evidence. No general hardware-validation or successful-fix claim is made by this source bundle.
